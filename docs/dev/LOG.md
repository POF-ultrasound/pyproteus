## 2026-11-22 — M2 clean-room ode45 (m2-ode45)
- `src/pyproteus/numerics/ode45.py`: `ode45`, `odeset`, `ODEResult` (`t`, `y`, `t_steps`, `y_steps`, `stats`, `stopped`, `message`; unpacks as `t, y`). Dormand–Prince 5(4) FSAL from Dormand & Prince 1980, control as described in Shampine & Reichelt 1997 / Shampine, Gladwell & Thompson 2003. Options: `RelTol`, `AbsTol` (scalar/vector), `NormControl`, `MaxStep`, `InitialStep`, `Refine`, `OutputFcn` (returning true stops after the step: hook for PROTEUS' wall-clock timeout), `BDF`/`MaxOrder` accepted and ignored like MATLAB. No MathWorks source opened.
- Probe method: a logging RHS records every call `(t, y, f)` MATLAB's ode45 makes (`tests/oracle/shims/ode45_probe.m`); Python's calls are compared bit for bit, attempt by attempt; candidate floating-point forms were scored against the log. Cases: decay (1 and 9 equations), rotation, van der Pol μ=5 (15 rejections), a 3-scale system, backward integration, default and explicit `MaxStep`, vector `AbsTol`, `NormControl`, sparse and dense `tspan`, `Refine` 1/2/4/7/8, step-size failure (y' = y²).
- Probed facts (R2025a): stage `j` = `y + h*(f1*a_j1 + f2*a_j2 + …)` left to right; the FSAL stage uses `h = tnew - t`; error = `absh * max(|f·e| / max(|y|,|ynew|,AbsTol/RelTol))` with the *unadjusted* `absh`; growth `absh/(1.25*(err/rtol)^0.2)` (×5 cap), first failure `absh*max(0.1, 0.8*(rtol/err)^0.2)`, then halving, no growth right after a failure; `hmin = 16*eps(t)`; last step stretched when `1.1*absh >= |tf - t|`; without `InitialStep` the first step is also capped by `|tspan(2) - tspan(1)|` (found: 1/976 on a 977-point tspan); `Refine` times `t + h*k/Refine`, evaluated at `s = (tq - t)/h`; continuous-extension coefficients identified by least squares on MATLAB's `Refine` output and recognised as rationals (`_BI`); `OutputFcn` gets `[t0 tf]` at `init` even for long `tspan`, is called only for steps with output, `done` passes `[]`; failure warning text and stopping step identical.
- MATLAB's `x^0.2` is not correctly rounded: bit-identical to Java `StrictMath.pow` = fdlibm `e_pow.c` (200 000 random inputs; libm/NumPy differ on ~10 %). Ported fdlibm `pow` (Sun notice kept, not MathWorks code) for the step-size rule; without it step sizes drift by an ulp after a few steps.
- Result: RHS calls, accepted/rejected steps, stats and solution at steps **bit-identical** to MATLAB on all 17 probe cases and on a Rayleigh–Plesset-like batch (shim `ode45_rp_rhs.m`, PROTEUS options, 1/4/16 bubbles, 234–400 steps), both in replay mode (Python RHS returns MATLAB's `f`) and with Python's own RHS when it uses fdlibm `pow`. With plain NumPy `**` in the RHS, same step counts and ≤ 1.5e-13 rel (class 1e-8). Dense output: one-equation systems bit-identical; several equations ≤ 1.1e-16 of the scale, 30–97 % of rows bit-equal (B-50).
- Found B-50 (dense-output evaluation order, open), B-51 (NumPy scalar `**` not correctly rounded on macOS arm64), B-52 (MATLAB elementary functions are fdlibm: matters for bit parity of every ported RHS). Q-2 (batch-dependent steps) recorded; MATLAB batch of 3 vs single bubble: 1.3e-6 rel difference.
- Tests: `tests/oracle/test_ode45.py` (22, ~5 s), `tests/unit/test_ode45.py` (29, pinned MATLAB values for CI).
- Not done here: `simple_RP` itself (separate M2 item; port it with fdlibm `pow` and `x*x`, see B-51/B-52), `ode23` + events (M4).

## 2026-11-20 — M0 numerics helpers (m0-setup)
- Setup PR merged (POF-ultrasound/pyproteus#1). Numerics on branch `m0/numerics`.
- `src/pyproteus/numerics/`: `matlab_round`, `sort`/`argsort` (stable both directions, MATLAB NaN placement, default dim), `find`/`sub2ind`/`ind2sub` (0-based, column-major), `interp1` (linear/nearest/pchip, NaN outside, `'extrap'`, fill), `gridded_interpolant` (1-D, extrapolates with its method), `pchip`, `ifft_symmetric`, `hilbert` (MATLAB axis rule), `conv`/`convn` (full/same/valid, trailing-singleton semantics), `rng`/`MatlabRNG` (`rand`, `randi`).
- MATLAB facts found by black-box probing (R2025a): `rng(0,'twister')` = MT seed 5489; `randi` = `floor(u*n)+lo` with one double per draw, interleaves with `rand`; `round(-0.4) = -0`; descending sort is stable with NaNs first; `conv(...,'same')` starts at `floor(nb/2)` (SciPy: `(nb-1)//2`); `hilbert` of a row vector works along the row; `griddedInterpolant` rejects unsorted points while `interp1` sorts them; `find(x,0)` errors; linear interpolation is `v0*(1-t)+v1*t`, bit-identical to MATLAB; `'nearest'` ties go to the upper point.
- pchip: slopes from Fritsch–Butland/Moler matched bit for bit; coefficient form `(3δ-2d0-d1)/h` did not (≈ 89 % equal, SciPy behaves the same); de Boor's divided-difference form gives bit-identical results (0 ulp).
- Oracle tests (first round): 55 numerics oracle tests + 16 harness (71); Hypothesis sweep at 300 examples per test passed (153 tests incl. unit, ≈ 30 s). FFT-based helpers within 1e-12 rel (FFTW vs pocketfft), the rest bit-identical.
- `tools/check_bans.py` now skips calls on `pyproteus.numerics` aliases (`nm.sort(...)`, `pyproteus.numerics.sort(...)`); a name bound to both numpy and the wrapper is flagged.
- Reviewer round 1 (CHANGES REQUESTED) fixed: linear interpolation was not bit-identical on flat segments (`v0 == v1`, ~8 % of such queries 1 ulp off) and with Inf/NaN neighbours at nodes; the exact rule was deduced by black-box probing (flat → `v0`; NaN from a zero weight at a node → node value; checked over all special-value triples). Also: `sort` along an axis ≥ ndim is now the identity (MATLAB trailing singleton), `ifft_symmetric` defaults to MATLAB's dimension, `interp1(...,'pchip')` drops NaN samples, vector `xq` with matrix `v` gives MATLAB's numel(xq)×m, `rand` size rules (negative → 0, trailing 1s dropped), non-integer `randi`/size arguments raise, empty `convn` raises, engine fixture wrapped so Hypothesis can print failing cases.
- Licensing note: the reviewer said the pchip coefficient grouping resembles MathWorks' `pwch.m` (from memory; nobody opened it). The grouping is the expansion of the Newton divided-difference form (de Boor) and was selected among algebraically equal forms by comparing with MATLAB's `unmkpp(pchip(...))` output; variables were renamed to divided-difference names and the derivation is documented in the code. Raised with the main session; the developer kept the form as clean-room (D-8).
- Sweep: 182 tests (unit + oracle) passed twice with `PYPROTEUS_ORACLE_EXAMPLES=300`.
- Reviewer round 2: SIGN-OFF. Opened B-20 (matrix `v` sign of zero, minor). Checker limitation (shadowed alias) documented.
- Not done: `randn` (out of scope per ROADMAP §5), `unique`/`intersect`/`ismember` index order (port case by case).
